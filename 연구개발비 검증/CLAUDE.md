# 연구개발비 검증 시스템

정부 R&D 사업 연구계획서의 연구개발비 예산표(PDF/HWP)를 받아
비목별 산정이 기준에 맞는지 검토하고 리포트를 만드는 웹 서비스.

## 핵심 원칙 (반드시 지킬 것)

1. **계산과 판정은 코드가, 읽기와 설명은 Claude가 한다.**
   - Claude는 예산표에서 숫자를 추출하고, 판정 결과를 설명하는 역할만 한다.
   - 비율·합계·한도 계산을 Claude가 직접 하지 않는다. 반드시 `engine/`의 규칙 엔진을 거친다.
2. **규정은 `rules/`의 JSON에만 둔다.** 코드나 프롬프트에 기준 숫자(비율, 한도)를 직접 적지 않는다.
3. **근거 없는 판정 금지.** 모든 판정에는 근거 조항(`rules/*.json`의 `근거` 필드)을 함께 표시한다.
4. **추출이 불확실하면 추측하지 않는다.** 값을 못 읽으면 `null`로 두고 "확인 필요"로 표시한다.
5. 판정은 3단계: `적정` / `확인 필요` / `부적정`.

## 폴더 구조

```
rules/      규칙 JSON (비목별 공식·한도·근거 조항)
schema/     Claude가 채울 추출 양식 (추출양식.json), 엑셀 출력 양식 (엑셀양식.json)
engine/     규칙 엔진 (추출 JSON + 규칙 JSON → 판정 결과)
prompts/    추출용·해설용 프롬프트
samples/    테스트용 예산표와 정답 결과
app/        웹사이트 코드
docs/       규정 원문 요약, 설계 메모
```

## 처리 흐름

1. 업로드: 예산표 파일 1개 이상 + 사업 정보(사업명, 전문기관, 연도)
   - 파일마다 기관명·기관 유형·역할(주관/공동/위탁)을 입력받거나 추출한다.
2. 변환: HWP/HWPX → PDF 또는 텍스트
3. 추출: Claude가 `schema/추출양식.json` 형식으로 숫자 추출 (파일당 1회, 한 번에 한 파일씩)
4. 판정: `engine/`이 `rules/`의 규칙으로 계산·판정
5. 해설: Claude가 판정 결과를 근거와 수정 방법과 함께 설명
   - 2~5단계는 파일별로 반복한다. 한 파일이 실패해도 나머지는 계속 처리하고, 실패 파일은 "처리 실패"로 기록한다.
6. 통합 검증 (파일이 2개 이상이고 같은 과제일 때): `rules/통합검증.json` 기준
7. 리포트: 엑셀 파일(`schema/엑셀양식.json` 형식) + 화면 요약

## 여러 파일 일괄 처리

- 같은 과제의 기관별 예산표인지, 서로 다른 과제인지 업로드 시 선택받는다.
- 같은 과제일 때만 통합 검증을 한다:
  - 기관별 합계 = 과제 총 연구개발비
  - 같은 연구자가 여러 기관에 중복 편성되었는지 (이름 + 소속으로 대조)
  - 위탁연구개발비가 주관기관 예산과 위탁기관 예산에 일치하게 기재되었는지
- 파일 간 비교·합산도 반드시 `engine/`에서 계산한다. Claude가 여러 파일 숫자를 직접 더하지 않는다.

## 엑셀 출력

- 시트 구성:
  1. `요약`: 기관별 1행 (기관명, 역할, 총액, 적정/확인 필요/부적정 건수, 종합 판정)
  2. `상세`: 기관 × 비목별 1행 (신청액, 기준 산정액, 차이, 판정, 근거 조항, 의견)
  3. `통합검증`: 기관 간 검증 결과 (해당 시)
  4. `처리기록`: 파일명, 처리 일시, 적용 규칙 기준일, 실패 사유
- 판정 셀 색상: 적정 = 초록, 확인 필요 = 노랑, 부적정 = 빨강
- 금액은 원 단위 숫자로 저장하고 천 단위 쉼표 서식만 적용한다 (텍스트로 저장 금지).
- 합계·차이 열은 엑셀 수식으로 넣어 사용자가 값을 고쳐도 다시 계산되게 한다.
- 파일명: `연구비검토_[사업명]_[YYYYMMDD].xlsx`

## 검토 항목 (rules/ 파일과 1:1 대응)

| 항목 | 규칙 파일 | 주요 검토 내용 |
|---|---|---|
| 인건비 | rules/인건비.json | 연봉 × 참여율 × 참여개월, 현금/현물 구분, 참여율 한도 |
| 학생인건비 | rules/학생인건비.json | 계상 기준 금액, 참여율 |
| 연구활동비 등 직접비 | rules/직접비.json | 비목 분류 적정성, 한도 |
| 위탁연구개발비 | rules/위탁연구개발비.json | 직접비 대비 비율 한도 |
| 간접비 | rules/간접비.json | 산정 기준 금액 × 기관 고시비율 |
| 기관부담금 | rules/기관부담금.json | 기관 유형별 부담 비율, 현금 비율 |
| 합계 검증 | rules/합계.json | 비목 합계 = 총액, 연차별 합계 |
| 기관 간 통합 검증 | rules/통합검증.json | 기관별 합계 = 과제 총액, 중복 인력, 위탁비 일치 |

※ 구체적인 비율·한도 숫자는 각 JSON 파일에만 기재한다. (기준 개정 시 JSON만 수정)

## 적용 기준

- 기본: 국가연구개발혁신법 및 시행령, 국가연구개발사업 연구개발비 사용 기준
- 사업별 공고문·전문기관 지침이 있으면 그것을 우선 적용한다.
- 현재 규칙 기준일: YYYY-MM-DD (규칙 수정 시 함께 갱신)
- 간접비 고시비율은 기관별·연도별로 다르므로 `rules/간접비_고시비율.json`에서 조회한다.

## 용어 통일

- "현금" / "현물"으로 표기 (현금성, 실물 등 혼용 금지)
- 금액 단위: 원(KRW), 천원 단위 표는 추출 시 원 단위로 환산
- 참여율: 0~100 사이 숫자(%)

## 개발 규칙

- 규칙 JSON을 추가/수정하면 `samples/`의 테스트를 모두 다시 돌려 정답과 비교한다.
- 개인정보(연구원 이름, 연봉)는 로그에 남기지 않는다. 업로드 파일은 처리 후 삭제한다.
- 리포트 하단에 항상 표시: "본 결과는 참고용 사전 검토이며, 최종 판단은 전문기관 기준에 따릅니다."
